# Управляемый маршрут книги

`workflow-start` записывает исходник и его SHA-256 в `workflow.json`. Дальше `status.workflow` показывает ожидаемый шаг и внутренний номер главы. CLI проверяет переходы до выполнения рабочих команд. Хуки записывают результаты успешных операций и проверяют их при переходе. Они работают при запуске через `bt.py` и установленную команду `bt`. После обрыва запусти `status`: записи переходов атомарны, блокировки освобождаются операционной системой.

```text
bt workflow-start <book.pdf> --work <папка>
bt status --work <папка>
bt workflow-advance <шаг> --work <папка> [--chapter N] [--file evidence.json]
```

Записывай подтверждение после действия. Свободный текст в полях подтверждает, что агент указал конкретные наблюдения. Код отдельно проверяет порядок, адреса, хеши, наличие машинных отчётов и полноту покрытия. Содержательность наблюдений проверяет читатель или судья.

## Подготовка книги

| Переход | Что должно быть в рабочих файлах | Поля JSON для `--file` |
|---|---|---|
| `brief` | Паспорт записан через `passport-set` | `audience`, `owner_decisions`, `provisional` |
| `ingest` | Успешный разбор, закрытые аномалии, английский `build --lang en --draft`, затем `artifact-check` | `coverage`, `source_anomalies`, `visual`, `artifact_sha256`, при наличии находок `artifact_findings` |
| `analyze` | Полное чтение переводимых единиц, `voice-set`, `term-candidates`, решения по всем рисункам | `map`, `voice`, `notes`, `figures`, `windows` |
| `bible` | Паспорт и действующие проверяемые правила | `terms`, `forms`, `rules` |
| `plan` | Чтение, риски и справочник подтверждены. Для каждого критерия описан проверяемый результат именно этой книги | `title`, `deliverable`, `scope_description`, `criteria` |
| `goal` | Агент прочитал активную цель после создания или при возобновлении | Результат `get_goal` с объектом `goal` |

Каждое текстовое поле содержит конкретный результат или основание неприменимости. Для `analyze` и поглавной редактуры укажи массив окон вида `{"units":["u-01-0001","u-01-0002"],"observation":"что проверено и замечено"}`. Перечисли все переводимые единицы соответствующей области по одному разу и в порядке реестра.

## План и цель до перевода

1. В `analyze` прочитай всю закреплённую область и связанные места. Собери карту, голоса, фактуру, имена и заметки. Для художественной прозы учитывай точку зрения, порядок раскрытия, хронологию, регистр, обращения, игру слов и культурные отсылки. В `risks` запиши как минимум одну адресованную проверку. Для каждой нужны уникальный `id`, `units` из области, `question`, `context`, `decision` и `sources` с `url` и `finding`. Если сцена и связанные места дают ответ, укажи `sources: []` и `context_only_reason`. Когда вопрос требует знаний извне, проверь надёжный источник и сохрани вывод. Дополнительные цитаты, варианты и проверку повторов храни в журнале решений. Разреши блокирующие вопросы по правилам навыка.
2. После `bible` выполни `bt workflow-advance plan --work <папка> --file plan.json`. В `criteria` используй AC-01–AC-09 для художественного EPUB. Для других книг используй `coverage`, `fidelity`, `terminology`, `readability`, `artifact`, `workflow`. Для каждого ключа запиши `requirement` с наблюдаемым результатом, `evidence` с проверкой, `units` с адресами и `risks` со списком ID из анализа. Свяжи каждый риск хотя бы с одним критерием, указав общий адрес. `bt` сохранит план и привяжет его к исходнику, области и результатам подготовки.
3. Сразу используй `workflow.goal_request.objective` из ответа или `bt status`. Сначала вызови `get_goal`, чтобы пережить прерывание между созданием и записью. Если такой активной цели ещё нет и текущая сессия свободна, вызови `create_goal` с точным `objective`, затем снова `get_goal`. Свой бюджет для книги задай только по указанию пользователя. Передай подтверждение как `{"goal":{"threadId":"...","objective":"...","status":"active"}}` в `bt workflow-advance goal --work <папка> --file goal.json`. `bt` сверяет содержание ответа, статус и SHA-256 плана. Подлинность ответа хоста обеспечивает прямой вызов инструмента агентом. Если инструмент цели недоступен, сохрани подготовку и сообщи, на каком шаге остановился маршрут. Если уже действует другая цель, потребуется решение о ней. При возобновлении в том же сеансе сверь привязку из `bt status` с `get_goal`.

При переносе работы в другую сессию используй точный `workflow.goal.objective`, получи активную цель этой сессии и повтори `workflow-advance goal` с её подтверждением. Привязка к новому сеансу сохраняет план и выполненные этапы.

`next`, `cite` и `submit` открываются только после подтверждённой цели. Для закрытия конкретных требований добавь `plan_sha256` из `workflow.goal` и `plan_review` в итоговый `acceptance` художественного EPUB или в `verify` остальных книг. `plan_review` имеет те же ключи, что `criteria`. Каждое значение содержит `verdict: "pass"`, те же `units` и конкретное `observation` о результате проверки. Хуки сверяют порядок, охват, ссылки на реестр и соответствие плану. Контекст, выводы исследования и качество русского оценивает агент по источникам и прочитанному тексту.

Эта подготовка обязательна для новых рабочих папок версии 2. Уже созданные папки версии 1 возобновляются по записанному маршруту, включая прежние квитанции приёмки.

## На каждую главу

Во всех вызовах `workflow-advance`, `next`, `qa` и `gate` передавай текущий `--chapter N`.

| Переход | Что требуется |
|---|---|
| `translate` | Для каждого пакета `next → cite → submit`. Повторно запускай `cite` после правки черновика. У всех единиц главы есть актуальный перевод. |
| `check` | `evidence --step check` для всех единиц главы. Правки через `edit --step check`; после правки запиши свидетельство для нового текста. |
| `edit` | Правки через `edit --step edit`. В подтверждении `observations` и `windows` с охватом главы, включая места без правок. |
| `read-target` | `evidence --step read-target` по окнам всей главы и при необходимости `edit --step read-target`. |
| `recheck` | Обнови утратившие актуальность проверки. Для завершения нужны актуальные свидетельства обоих проходов. |
| `gate` | `qa`, решения по кандидатам через `decide`, затем `gate` с вердиктом `pass`. |

Гейт заново сверяет актуальность. Если нужно исправить уже пройденную главу, вызови `workflow-reopen --chapter N --reason "что требует перепроверки"`. Принятый перевод сохраняется, переходы проверок этой и последующих глав и завершающих шагов книги открываются заново. Свидетельства можно использовать повторно, пока совпадает отпечаток текста и решений.

Если решение справочника изменилось посреди перевода главы, возьми список `stale` из `status --chapter N` и перепроверь эти единицы через `edit --step check`. Хук разрешит на шаге перевода исправить только устаревшие единицы.

## Закрытие книги

| Переход | Что требуется |
|---|---|
| `crossbook` | Повторно подтверждённый гейт каждой главы. В JSON передай `consistency` с парами адресов и `findings` с итогом. |
| `index` | При наличии предметного указателя сделай черновую сборку, вызови `index-bind --positions` с её файлом позиций, закрой привязки и дубли. В JSON передай `bindings` с результатом или основанием неприменимости. |
| `build` | Финальная сборка по всей книге без `--draft`. |
| `verify` | На финальном файле выполни `artifact-check` и визуальную сверку. Передай `artifact_sha256`, `artifact_checks`, `visual`, `coverage`, `unverified`. |
| `acceptance` | Для художественного EPUB после `verify` передай структурированные [доказательства AC-01–AC-09](fiction-epub-acceptance.md). |

Для `ingest` и `verify` используй SHA-256 из `artifact-check`. Машинные находки исправь и перепроверь либо укажи каждую оставшуюся по ID в `artifact_findings` с конкретным основанием. В `visual` укажи просмотренные адреса и то, что было видно.

Для EPUB код требует указать в брифе `passport.source.genre` и закрепляет жанр. Допустимы `fiction`, `nonfiction` и `technical_book`. Исправление неверно выбранного жанра начинается с нового брифа в новой рабочей папке. Для ранее завершённого управляемого художественного EPUB `status` предложит новый шаг `acceptance`, используя сохранённые предыдущие шаги и актуальные доказательства. На этом шаге при необходимости повтори `artifact-check` для финала или `artifact-check --selftest` для точной английской сборки. После правки текста используй `workflow-reopen`.

Старые рабочие папки с уже существующим реестром доступны через прежний интерфейс. Создавай новые книги в управляемой папке.

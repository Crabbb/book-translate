**book-translate** это навык для LLM-агента (Claude Code, Codex и других) и CLI `bt`. Вместе они переводят техническую книгу с английского на русский целиком: с единой терминологией, сохранённой вёрсткой и проверяемыми доказательствами по каждому абзацу.

Модель здесь переводчик, а не весь процесс. Всё, что можно проверить кодом, проверяет код. То, что требует понимания смысла, остаётся за агентом, и каждое его решение записывается с причиной.

## Почему не «просто попросить модель перевести»

Текст от большой модели читается гладко, и в этом проблема: ошибка смысла выглядит так же уверенно, как верный перевод. На книге в 300 страниц это превращается в системные поломки.

| Что обычно ломается | Что делает book-translate |
|---|---|
| Один термин переводится тремя способами в разных главах | Живой справочник: у термина один вариант, причина и формы по падежам. Код сверяет перевод с ним |
| Модель смягчает автора: «должен» вместо «следует», «помогает» вместо «обеспечивает» | Паспорт книги задаёт правила модальности и голоса, отдельная проверка ловит расхождения |
| Куски текста теряются или появляются из ниоткуда | Книга разбита на единицы с учётом каждого глифа PDF. Потеря останавливает разбор |
| Вёрстка, таблицы, ссылки и указатель исчезают | Tagged PDF разбирается в структуру и собирается заново: те же стили, рисунки, код, ссылки, новая пагинация |
| Текст на растровых рисунках остаётся английским | Каждый рисунок просматривается, транскрипция становится единицей перевода и выводится под подписью |
| Инструкции внутри книги об LLM выполняются как команды | Текст книги всегда данные. Промпты в книге сохраняются рядом с переводом |
| «Я всё проверил» без доказательств | Сверка привязана к отпечатку текста. Изменился перевод или термин, и доказательство аннулируется |

## Как идёт книга

<p align="center"><img src="docs/assets/pipeline-ru.svg" alt="Схема: паспорт, разбор PDF, анализ, справочник; для каждой главы перевод, сверка, правка, чтение, повтор, гейт и судья; затем межглавная сверка, указатель и сборка" width="100%"></p>

Состояние хранится на диске, поэтому работа переживает обрыв сессии: `bt status` пересчитывает его из файлов. Единицы приходят пакетами, а перед отправкой `bt cite` показывает правила пакета и связывает перевод с терминами справочника.

## Справочник живой, а не глоссарий в начале

<p align="center"><img src="docs/assets/bible-ru.svg" alt="Запись справочника и цепочка: решение изменилось, единицы устарели, доказательства аннулированы, агент правит каждую" width="100%"></p>

Термин определяет только справочник этой книги. Если решение меняется на 200-й странице, код сам находит все затронутые места. Переводчику не нужно помнить, что он решил в первой главе.

## Что показала первая книга

Навык откалиброван на настоящей IT-книге: 300 страниц, 95 рисунков, около 86 тысяч слов, предметный указатель. Каждую часть после всех локальных проверок читал независимый судья, другая модель. Он видел текст, но не рассуждения переводчика, и мог только ставить диагноз.

**Главный вывод неудобный.** Все 32 ошибки смысла прошли локальные проверки и нашлись только у судьи. Переводчик, проверяющий сам себя, систематически не видит собственных ошибок. Поэтому судья входит в процесс, а находки превращаются в правила навыка, чтобы следующая глава начиналась с меньшим числом таких ошибок. После исправлений второй раунд дал 0 major во всех частях.

Вот какие ошибки это были. Ни одна не бросается в глаза при чтении только русского текста:

| Оригинал | Гладкий перевод | Что сломалось | Стало |
|---|---|---|---|
| `sensitive data` | важные данные | Меняется круг защищаемых сведений | чувствительные данные |
| `should` | должен | Рекомендация стала обязанностью | следует |
| `protecting against` X | защита X | Направление защиты обратилось | защита от X |
| `tamper-evident` | защищённый от подделки | Обнаружение подмены стало её предотвращением | позволяющий обнаружить вмешательство |
| `intractable` | неразрешимый | Ресурсное ограничение стало принципиальной невозможностью | практически не поддающийся решению |
| `performance` о скорости | результативность | Обещан рост качества вместо скорости | производительность |

Судья находил и дефекты самого навыка: подпись рисунка отрывалась от его перевода, содержание оказывалось перед обложкой, рисунок после указателя терялся. Всё это исправлено в коде и закреплено тестами.

**Итог:** 3341 единица, 773 ссылки указателя, 335 страниц сборки, 0 находок автоматической проверки PDF.

## Быстрый старт

Нужны [uv](https://docs.astral.sh/uv/), [Typst 0.15.1](https://github.com/typst/typst/releases) и шрифты Libertinus Serif, Source Sans 3, Liberation Mono. Исходный PDF должен быть тегированным (Tagged PDF).

```bash
git clone https://github.com/Crabbb/book-translate.git
cd book-translate
uv sync
uv run pytest -q
```

Подключите навык, скопировав или связав `skills/book-translate` в каталог навыков агента (например, `~/.claude/skills/`), и запускайте агента из этого репозитория, чтобы работала команда `uv run bt`. Дальше достаточно попросить:

> Переведи книгу `book.pdf` на русский, рабочая папка `work/mybook`.

Агент ведёт процесс сам и спрашивает вас, только когда не может продолжать. Для сборки укажите пути:

```bash
export BT_TYPST=/path/to/typst
export BT_FONTS=/path/to/fonts
uv run bt build book.pdf --work work/mybook
```

## Честно об ограничениях

- **Проверено на одной книге.** Проверка на второй, не участвовавшей в калибровке, ещё впереди. Заявлять, что навык работает на любой книге, рано.
- **Только EN → RU** и только Tagged PDF. Для других издательств нужен свой профиль вёрстки.
- **Качество зависит от судьи.** Без него ошибки смысла остаются: это измерено, а не предположено.
- **Это не бесплатно и не мгновенно.** Книга читается целиком и несколько раз, это заметный расход токенов и времени.
- **Письменности без шрифтов** (арабская, китайская, деванагари) сейчас остаются только на растре рисунков.
- Отзыв «ошибок нет» навык не выдаёт никогда: итог называет покрытие и то, что не проверено.

## Авторские права

Репозиторий содержит только инструмент. Книг, их фрагментов и переводов здесь нет, и они не должны сюда попадать (`books/` и `work/` в `.gitignore`). За право переводить и распространять конкретную книгу отвечаете вы.
